## Remote release identity and wider unknowns

The GitHub release is the authority for the exact committed SHA and successful
remote CI URL. The publication procedure waits for that exact candidate's CI,
then creates a new annotated v0.5.0 tag and verifies remote tag resolution.
Published historical tags are never changed. Git sync alone is not publication.

This release distributes a stricter contract; it does **not** certify unqualified
full-baseline acceptance for the starter or any adopter. Full acceptance still
requires applicable current freshness, analyzer installation/compatibility,
reviewed findings and product/host evidence. Remaining selected deeper-tool
proofs (including cohesion, Interrogate, Vulture, Bandit, coverage, deptry,
pip-audit and Import Linter as applicable) are UNKNOWN here, not waived passes.
The selected ty beta exception remains visible with its existing revisit rule.
The bounded Cosmic Ray compatibility probe is a synthetic tool test, not a
mutation score for the application. Real-adopter migration and fresh-session
discovery for 0.5.0 are not established by helper tests; the older Windows Codex
receipt remains historical. Backplane is disabled and whole-heavy readiness
remains pending. No dependency refresh or native plugin installation is performed.

Automatic lane/evidence/PRD checks, evidence invalidation and three-way upgrade
merging remain proposed in the [design record](../engineering/strict-adoption-design.md).
The helper still accepts absent/pending profiles during configuration and
reports runtime readiness unverified. The documented acceptance gate, not a
new CLI gate, prevents calling that completed adoption.
