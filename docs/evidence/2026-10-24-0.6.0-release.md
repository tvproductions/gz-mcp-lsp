# 0.6.0 release verification and limits

User scope: a lightweight template-native entry teaching canonical update and
migration methods, explicitly authorized for release as 0.6.0. This is the
single exception to zero authored skills. Generic dependency/update workflows
remain in gz-skills; no upstream skill is copied or modified.

## Delivered behavior

- One source at `templates/skills/update-gz-template/SKILL.md`, with one checked
  wheel-resource copy. Configure previews/seeds the project-scoped
  `.agents/skills/update-gz-template/SKILL.md` alongside existing managed files.
- Differing local skill content blocks all writes; symlinks and alternate
  repository discovery copies require reconciliation. Failed skill creation
  rolls earlier managed outputs back. Existing project skills are preserved.
- [Canonical updating](../updating.md) defines review/update modes and the
  pre-skill bootstrap path. A portable ZIP contains only the reviewed skill.
  Bootstrap records its own source without relabeling the adopter's old baseline.
- Existing baseline policy, explicit lane requirements, analysis/acceptance and
  SemVer/major-PRD rules remain in force. No plugin/runtime/tool pin, file schema,
  ordinary hook or CI contract changes. uv.lock changes only template metadata.

## Limits

Actual fresh-session host discovery/invocation has not been established for
this new skill. The helper targets the project's .agents discovery directory;
other hosts require native verification. Portable source, file placement and
installed-artifact proof are not host acceptance. Global same-name skills must
also be inventoried by the adopter; the helper checks repository-local surfaces.

This is a small guide and managed-file capability, not automatic merging,
release authorization, dependency refresh or conformance certification. Broader
freshness/analyzer/host proofs and deterministic evidence/PRD validation remain
open as disclosed by the 0.5 release. Existing Cosmic Ray and complexity-contract
receipts retain their observed scope; no whole-application mutation result or
real-adopter migration is implied here. No adopter or native plugin cache is
changed by publishing this template release.
