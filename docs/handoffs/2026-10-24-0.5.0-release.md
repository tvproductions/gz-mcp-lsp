# 0.5.0 delivery and continuation

The user authorized a release so downstream adopters receive the previously
unreleased Astral policy and clarified greenfield/brownfield migration stories.
The selected minor is 0.5.0; publication identity and exact-commit CI belong to
the GitHub release. Recheck live tags/releases/history before further work.

Read [the release receipt](../evidence/2026-10-24-0.5.0-release.md),
[adoption/upgrade runbook](../adoption-0.5.md),
[baseline policy](../baseline-policy.md), [versioning](../versioning.md) and
[design/decision record](../engineering/strict-adoption-design.md).

Confirmed policy: Python-exclusive template, mandatory explicit lite/heavy lanes
with equal applicable engineering foundations, required analysis at adoption and
release acceptance, incremental migration to compliance, independent SemVer and
a newly written PRD for every major including 1.0.0. The primary purpose is the
maintainer's personal consistency; public reuse is welcome. Future Go and
language/environment-specific CLI/TUI/web/desktop guidance require their own
designs. Heavy retains SP + Backplane + gz-skills as the intended stack;
Backplane readiness/activation remains deferred, not replaced by another lane.

The helper remains configuration-only. Automatic conformance/PRD/evidence
validation and three-way upgrade merging are not implemented. An absent/null
profile is still accepted during configuration, but cannot mean completed
adoption under 0.5 policy. Both lane settings and the reviewed manual upgrade
path have disposable fixture proof. The canonical-path test fix removes the
macOS TMPDIR workaround without changing helper behavior. Runtime/tool/plugin
pins, schemas, routine hooks and CI contract are retained.

Next work: scope the remaining deterministic enforcement from the design;
complete remaining analyzer/freshness/host proofs; and perform a real-adopter
pilot only in an authorized target. Preserve old receipts as historical. Do
not claim 100% baseline acceptance from this release, helper status, or prose.
An independent future release still requires its own authorization; do not move
published tags or rewrite historical provenance. No downstream project has been
mutated by publishing the starter.
